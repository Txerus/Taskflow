# TaskFlow — règles permanentes
Application Windows française de productivité professionnelle. Garder packages/ui et packages/core indépendants d’Electron. Lire PLAN.md et PROGRESS.md à chaque reprise.
Design : suivre PRODUCT.md et DESIGN.md ; compétences frontend-design, Impeccable, web-design-guidelines et no-slop-ui. Interface sobre type Linear/Things : pas de hero, métriques décoratives, dégradés, glassmorphism ou cartes imbriquées. Neutres OKLCH, un accent, IBM Plex Sans/Mono local, Lucide, corps 14px, grille 4px, rayons 4–8px, mouvement court réduit selon préférence.
UX : palette Ctrl+K, raccourcis, états chargement/vide/erreur, annulation suppression, focus visible, navigation clavier, alternatives clavier au glisser-déposer, barre de titre intégrée et dates fr-FR.
Code : TypeScript strict, DataStore async, composants réutilisables, validation aux frontières, tests Vitest et Playwright Electron. Après corrections, tests puis commit ; noter les échecs d’environnement sans prétendre avoir validé ce qui n’a pas tourné.
Phases : Phase 1 tâches, Phase 2 pages Tiptap, Phase 3 OAuth et mails, Phase 4 bonus. Validation utilisateur ET tests/installeur réussis avant chaque phase suivante. Ne pas créer RAPPORT_FINAL.md avant tous les critères finaux.
Sauvegarder une archive durable du travail avant toute interruption ; le filesystem de travail peut disparaître.
